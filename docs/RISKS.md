# Risks

| Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|
| Evon access does not arrive | Low | Medium | **Mitigated in Phase 6**: Swappable provider architecture in `server/llm/` with automatic fallback to `server/llm/rules.js` on error or 8s timeout. Rules baseline tested at 95% accuracy on fixtures with zero credit usage. |
| Browser audio format is not accepted by an API | Low | High | **Mitigated in Phase 5**: Browser uses Web Audio API to record and downsample audio directly to 16 kHz mono 16-bit PCM WAV before upload; no ffmpeg needed on server. |
| Noisy audio lowers accuracy | High | High | **Mitigated in Phase 9**: Built dedicated normalisation pipeline (`server/llm/normalize.js`) stripping fillers, zero-width characters, discourse markers, and detecting speech self-corrections. Calibrated confidence policy triggers `needsConfirmation: true` when confidence < 0.8 or corrections are detected. Added `/dev/collect` to gather empirical noisy/quiet transcripts. |
| The 5,000 credits are exhausted | Medium | High | **Mitigated in Phase 8 & 11**: Server in-memory TTS cache (`server/ttsCache.js`) caches static question audio so repeated plays cost 0 credits (`X-Cache: HIT`). Read-back TTS splits dynamic values from static confirmation prompts, ensuring static prompts hit cache on 2nd and subsequent fields. Large on-screen Yes/No buttons enable tap-based confirmation saving STT/TTS calls. Hourly rate limit `MAX_LIVE_CALLS_PER_HOUR` (default 120 calls/hr) blocks runaway loops. Client includes typed test mode and "Mute voice" toggles to complete full forms with 0 live API calls. **Estimated credit use per form:** ~18–24 live calls (~450 Timbre chars) per full voice form, allowing ~150–200 full forms on the 5,000 credit budget, and infinite forms in typed mode. |
| Shared-link microphone requires HTTPS | Medium | Medium | Demo on localhost or an HTTPS host; test microphone permission before recording. |
| Names and numbers are misheard | High | High | **Mitigated in Phase 7, 9, 10 & 11**: Confirmation flow now fully implemented (`server/forms/confirmPolicy.js`, `server/forms/formEngine.js`, client state machine). Read-back plays grouped digits with natural pauses (phone 5+5, Aadhaar 4+4+4, bank account groups of 4). Sensitive fields are masked on-screen (last 4 visible) but spoken in full for verification. Silence or ambiguous speech ("sari, aana illai") strictly never confirms sensitive values. Rejection ("illai", "wrong") clears the field and triggers adaptive re-prompting (spell mode for names, smaller groups for numbers). Max 3 rounds per field moves on with `needsOperatorHelp` highlight on review screen. |
| Demo overclaims capability | Medium | High | Use the safety checklist and state that the app is a prototype that does not submit forms. |
| Time runs out before a stable demo | High | High | Freeze scope to one form and one correction; cut PWA/Evon work before core flow work. |
